# ロードマップ

## P0: 実環境の受け入れ

追加機能より先に、[`TEST_PLAN.md`](./TEST_PLAN.md) のClaude Artifact実機項目を完了する。

- `window.storage` の未存在キー、成功戻り値、例外形状を確認
- Artifactを閉じ直した後と更新後の永続性を確認
- 同一Claudeアカウントの複数端末で同じデータを確認
- 同月で別イベントを追加した際のマージを確認
- 同一イベント編集と削除復活防止を確認
- 保存失敗時の入力保持と再試行を確認
- 実データ相当のエクスポート / インポートを確認

実際のAPI挙動が想定と異なる場合は、再現手順、期待結果、実際の結果、例外、戻り値、データ消失リスク、影響月キー、回帰テストを記録してから修正する。

## P1: 小さな利便性改善

P0完了後、必要性を確認して個別に設計する。

- 別月への安全な予定移動
- 予定検索
- 予定複製
- 色タグのカスタマイズ
- バックアップ件数・概算容量表示
- 競合時の採用結果表示
- 破損退避キーの一覧・削除支援
- インポート前の差分プレビュー

## 設計前提を変える候補

次は単純な機能追加として着手しない。個人スコープ、月単位キー、ポーリングなし、自己完結した単一HTML成果物という前提への影響を先に評価する。

- 繰り返し予定
- 通知
- 外部カレンダー同期
- 参加者・他ユーザー共有
- サーバー側の同期や認証
