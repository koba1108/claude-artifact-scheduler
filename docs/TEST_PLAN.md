# 手動テスト手順

## 1. 通常ブラウザのプレビューモード

`bun run build` 後の `dist/index.html` を静的HTTPサーバー、または `bun run dev` で開く。黄色い「プレビューモード」表示が出ることを確認する。

### 基本表示

- [x] 380px幅で横スクロールが発生しない
- [x] 当月と今日が選択される
- [x] 前月・翌月・今日へ移動できる
- [x] 予定0件の空状態が表示される
- [x] 設定・追加ボタンが操作できる

### 予定の追加

- [x] タイトルだけで終日予定を登録できる
- [x] 開始時刻のみの予定を登録できる
- [x] 開始・終了時刻の予定を登録できる
- [x] 色がカレンダーのドットと予定カードへ反映される
- [x] 800ms以内は「保存待ち」、その後「保存完了」になる
- [x] 同じ日に複数件登録すると時刻順になる

### 入力検証

- [x] 空タイトルは保存できない
- [x] 終了時刻だけ指定するとエラーになる
- [x] 終了時刻が開始時刻以前ならエラーになる
- [x] 表示月の外の日付は選択できない
- [ ] 日本語IME変換中のEnterで意図しない保存が起きない
- [x] `Cmd/Ctrl + Enter` で保存できる

### 編集・削除

- [x] 予定カードから編集できる
- [x] タイトル、時刻、メモ、色を変更できる
- [ ] 削除確認後に一覧から消える
- [ ] 削除後の保存が成功する

### プレビュー固有

- [ ] ページ再読み込みでデータが消える
- [x] `localStorage`、`sessionStorage`、IndexedDBに値が作られない

## 2. Claude Artifact実機

`dist/index.html` 全文をHTML Artifactへ反映する。同じArtifactの最新versionでテストする。

### window.storage 基本動作

- [ ] 黄色いプレビューモード表示が出ない
- [ ] 初回追加後に「保存完了」と更新時刻が出る
- [ ] Artifactを閉じて再度開いても予定が残る
- [ ] Claudeアカウントへ再ログイン後も予定が残る
- [ ] 再読み込みボタンで最新データを取得できる

### 複数端末

端末Aと端末Bで同じClaudeアカウント・同じArtifactを開く。

- [ ] Aで8月、Bで9月を編集し、両方の変更が残る
- [ ] AとBが同じ月へ別IDの予定を追加し、後から保存しても両方残る
- [ ] Aが追加した予定をBの再読み込みで取得できる
- [ ] Aが予定を削除し、Bで古い状態から別予定を追加しても削除済み予定が復活しない
- [ ] 同一イベントをA/Bで編集した場合、`updatedAt` が新しい方になる
- [ ] 更新元ラベルが月キーの最終保存者として表示される

### タブ復帰

- [ ] タブを非表示にした直後、pending保存がflushされる
- [ ] 別端末で更新後、タブ復帰すると1回だけ再取得される
- [ ] 短時間に可視・不可視を繰り返しても15秒以内の再取得が連打されない

## 3. バックアップ

### エクスポート

- [x] 設定からバックアップJSONを作成できる
- [x] `format`、`schemaVersion`、`exportedAt`、`values` が含まれる
- [x] 複数月キーとmetaキーが含まれる
- [x] コピーボタンでクリップボードへコピーできる
- [x] 最終バックアップ時刻が更新される

### インポート

別の月へテスト予定を含むバックアップを使う。

- [x] JSON不正時に保存せずエラー表示する
- [x] 形式不正時に保存せずエラー表示する
- [x] 正常JSONは月数を確認してから実行する
- [x] 既存の別IDイベントを消さずに追加できる
- [x] 同じIDは新しい `updatedAt` の値を採用する
- [x] import後に現在月が再取得される

## 4. 障害系

実機環境で再現できる範囲だけ行う。既存の本番データではなくテスト用Artifactを推奨する。

### set失敗

- [x] 保存失敗時に予定が画面から消えない
- [x] 「閉じると失われる」警告が出る
- [x] 再試行ボタンが表示される
- [x] 通信復旧後の再試行で保存できる
- [ ] 保存失敗中の月移動を防止する

### JSON破損

テスト用キーへ不正JSONを保存できる場合のみ実施する。

- [x] parse失敗を通知する
- [x] `:broken:<epoch-ms>` キーへ元文字列が退避される
- [x] 元の月キーが空のv1データへ復旧する
- [x] brokenキーがエクスポートへ含まれる
- [ ] brokenキーがインポート対象にならない
